让 AI 直接读写并部署 Google Apps Script，无需打开浏览器或安装 clasp

需求概括（附 ID）：qiita:228dfa134c76e15ab1a8。核心痛点是 AI 改完 GAS 代码后仍要人工打开浏览器部署，受限电脑装不了 Node.js/clasp，长代码难定位函数、跨文件同名函数会静默覆盖。

为什么值得做：需求来自真实 GAS 使用场景，现有工具几乎都是 MCP 服务器形态且依赖本地 Node.js，恰好没解决“受限电脑装不了 Node.js/clasp”的空缺；作者自己的「秀GASマネージャー」虽覆盖核心需求，但无安装分发、无多用户配置界面，普通 GAS 用户难以直接使用。风险是 Google Apps Script API/OAuth 首次授权通常仍需浏览器，且作者已有个人 MCP 服务器，官方 clasp 也在演进；需要把差异化明确放在“免 Node、免手动部署、函数级索引与冲突提示”。

建议形式：Windows 免安装单文件桌面工具（内嵌运行时）＋浏览器扩展桥接，首次 OAuth 后由工具直接调用 Apps Script API。

最小可行版本的 3 个核心功能： - Google 账号 OAuth 后列出脚本项目，拉取/编辑/保存文件。 - 函数索引与跨文件同名函数冲突提示。 - 一键创建部署版本并返回 Web App URL。

怎么验证有人要：回复 qiita 原帖；发到 Qiita 的 #GAS、#GoogleAppsScript 标签和 Google Apps Script 社区；在 X 上带 #GAS 发布演示。

预计开发天数：12～16 天。

#2Chrome 扩展

检测网站按 User-Agent 返回不同内容（如隐藏给 AI 的指令）的浏览器扩展

5.1综合分

需求概括（附 ID）：hn:50168676。网站会根据 UA 返回不同内容，普通用户无法知道自己看到的页面与 AI 爬虫或其他设备看到的内容有差异。

为什么值得做：竞品检查为 weak，现有工具几乎都是“UA 切换器”，需要用户自己切换、自己肉眼比对；没有工具自动以多个 UA（尤其 AI 爬虫 UA）抓取同一页面并高亮差异。风险是跨域抓取受 host permissions 和反爬限制，部分站点会封禁或返回假内容；UA 伪装也可能有伦理与商店审核问题；付费意愿仅 2，适合做轻量免费/捐赠或隐私工具品牌。

建议形式：Chrome 扩展，输入 URL 或对当前页生成对比报告。

最小可行版本的 3 个核心功能： - 以普通 Chrome、Googlebot、GPTBot/ClaudeBot 等 3～5 个 UA 抓取同一 URL。 - 对正文、隐藏文本、关键差异做结构化 diff 并高亮。 - 保存本地对比记录，对明显差异给出告警。

怎么验证有人要：回复 HN 原帖；发 Show HN；发到 r/webdev、r/privacy、Privacy Guides 社区。

预计开发天数：4～6 天。

为什么值得做：现有搜索结果多是教程代码或需自行部署的 GitHub 脚本，缺少开箱即用、带配置界面（添加 RSS、设定早晚时间、自动去重）的网页工具；作者自己的 GAS 脚本只是个人配置，没有配额/失败处理。风险是 GAS 配额与触发器限制、RSS 源反爬、Google OAuth 验证；付费意愿 2，适合免费增值或模板化产品。

怎么验证有人要：回复 qiita 原帖；发到 Qiita #GAS #RSS、Zenn、r/rss。

预计开发天数：5～7 天。

为什么值得做：作者已用 AutoHotkey v2 写了 NoTabKana 并开源，但只是个人 AHK 脚本，缺安装包、配置界面、开机自启、对其他 IME 的兼容和更新分发；竞品检查 weak，现有方案都是个人 AHK 脚本。风险是低级键盘钩子可能被杀软误报、不同 Windows/IME 版本行为差异、作者已有开源脚本；但“打包成可安装桌面应用”的空缺明确。

建议形式：Windows 托盘桌面应用，低级键盘钩子＋设置界面。

最小可行版本的 3 个核心功能： - 数字键直接选择候选词，必要时自动补 Tab。 - =/- 翻页及开关快捷键。 - 安装包、开机自启、基础设置界面。

怎么验证有人要：回复 qiita 原帖；发到 Qiita #Windows #IME、GitHub Release、X 日语输入社区。

预计开发天数：5～8 天。

  • VS Code 原生 UI 微调类：如 gh:microsoft/vscode#344616、gh:microsoft/vscode#340650、gh:microsoft/vscode#343904、gh:microsoft/vscode#345151、gh:microsoft/vscode#343293。受官方 API 限制，很多只能改 CSS 或依赖非公开命令，官方随时可能实现，付费意愿多为 1～2。
  • 已有成熟免费方案且差异化弱：如 gh:microsoft/PowerToys#51759（7-Zip/WinRAR/Inno Setup 已覆盖）、hn:49806516（LinearMouse 等已可关鼠标加速）、gh:microsoft/PowerToys#50482（已有 ThreeFingerDragOnWindows）、hn:49861720（已有 better YouTube preview）。获客难，除非有明确体验优势。

英文、日文、中文社区的差异
  • 日文社区（qiita）：需求大量集中在日常业务自动化和桌面效率，如 GAS/Excel、Windows 日语 IME、收据 PDF、Search Console、Kakuyomu 数据、NDL 分类、家务提醒。常见表述是“個人スクリプトで部分解決”“現場でインストールできない”“非技術者には難しい”，说明机会主要在把个人脚本做成开箱即用、有界面、有安装包的小工具。付费意愿多为 2～3，适合低价或免费增值。机会点是“降低配置门槛”和“适配日本本地格式/习惯”（和历、敬称、发票登记号、日本地址、日语输入）。

  • 中文社区：本批数据没有中文社区来源（平台字段只有 qiita、hn、github、forum、se），因此无法从样本判断中文社区的需求侧重和机会，不能编造差异；上面的比较只代表日文与英文样本。
